# Naming collisions & intro to namespaces

- C++ requires that all identifiers be non-ambiguous. If two identical identifiers are introduced such that the compiler or linker can't tell them apart, *the compiler or linker* with produce an error referred to as a **naming collision**.

## Naming collision

```c
//a.cpp

#include <iostream>

void myFnc(int x){
    std::cout << x;
}
```
```c
//main.cpp

#include <iostream>

void myFnc(int x){
    std::cout << x*2;
}

void main(){
    return 0
}
```

- This program will compile, as there is no ambiguities within each file, but at the link stage, the ambiguity among a.cpp:myFnc(int x) and main.cpp:myFnc(int x) will cause a linker error. myFnc doesn't need to be called for this to occur.

- Naming collisions typically occur when two identically named globals or functions are introduced into separate files within the same program (linker error) or are introduced into the same file (compiler error).

## Scope regions
- Scope region is an area of source code where all identifiers are considered distinct from names declared in other scopes.
    - Analagous to cities: 123 Jefferson St in San Diego is distinct from 123 Jefferson St in Charlottesville.

- A function body is an example of a scope region. Identifally named identifers within two different functions are allowed because they're only accessible within the scope of the function. 

- *A name declared within a scope region is distinct from any identical name declared in another scope region.*

## Namespaces

- A namespace is another type of scope region (namespace scope) that allows you to declare names inside of it for disambiguation. Names declared in it are isolated so they can exist without conflict.

-  A namespace can only include declarations and definitions, no executable statement other than ones apart of definitions.


### The global namespace

- Anything not defined in a class, function, or namespace is considered to be part of the implicitly defined namespace called the *global namespace/global scope*

- The naming collison example has both instances of myFnc in the global namespace, which violates rule that all names in the scope region must be unique.

*Two imporant things to know*
    1. Identifiers in the global scope are in scope from the point of declaration to the end of the file.
    2. Variables can be defined in the global namespace, but should generally be avoided because it's evil.

```c
#include <iostream> // imports the declaration of std::cout into the global scope

// All of the following statements are part of the global namespace

void foo();    // okay: function forward declaration
int x;         // compiles but strongly discouraged: non-const global variable definition (without initializer)
int y { 5 };   // compiles but strongly discouraged: non-const global variable definition (with initializer)
x = 5;         // compile error: executable statements are not allowed in namespaces

int main()     // okay: function definition
{
    return 0;
}

void goo();    // okay: A function forward declaration
```

### The std namespace

- Originally you could use C++ standard library identifiers without `std::` but this caused problems where you would have collisions if you included parts of the standard library, or compiling between different standards caused errors due to additional identifiers between standards.

### Namespace identifiers

- When you use an identifier that is defined inside a non-global namespace, i.e. the std namespace, you need to tell the compiler that the identifier lives inside the namespace.

**Explicit namespace qualifier std::**

- Straightforward: to use `cout` from the `std` namespace you can use the `std::` prefix.

```c
#include <iostream>
int main(){
    std::cout << "Used explicit namespace qualifier std:::" << '\n';
    return 0;
}
```

**Scope resolution operator**

- The `::` symbol is also known as the *scope resolution operator*.
    - The identifier to the left of the symbol identifies the namespace that the name to the right of the symbol is contained within. No left symbol will be assumed to be the global namespace.
    - `<namespace>::<name>`

- *Best practice:* Use explicit namespace prefixes to access identifiers defined in a namespace.

**`using namespace std` (and why to avoid it)**

- a *using-directive* statement allows for access to the names in a namespace without using the namespace prefix.

```c
#include <iostream>

using namespace std; // this is a using-directive that allows us to access names in the std namespace with no namespace prefix

int main()
{
    cout << "Hello world!";
    return 0;
}
```

- When this code compiles, the compiler will be able to match cout with std::cout because of the using-directive. However, this is bad practice because you reintroduce the standard-library naming collision problems *that were the reason for the namespaces being added in the first place.*

**Curly braces & indented code**

- Curly braces deliniate scope region nested within another scope region.

> They may also be used for other purposes, like *list initialization*

- Sometimes identifiers defined outside the curly braces may still be part of the scope defined by the curly braces rather than the surrounding scope (i.e. function parameters)

- *Example:*
```c
#include <iostream>

void foo(int x)             // foo is defined in the global scope, x is defined within the scope of foo()
{                           // braces used to deliniate nested scope region for foo()
    std::cout << x << '\n'; // The identifier 'x' is accessible inside this scope despite it being declared outside of the braces.
}                           // x goes out of scope

int main()
{ // braces used to deliniate nested scope region for function main()
    foo(5);
    int x { 6 }; // x defined within this scope
    std::cout << x << '\n';
    return 0;
} // x go out of scope
// foo and main (and std::cout) go out of scope here (end of file)
```

- The #include and function definitions are in the global scope, so they're not indented. Statements inside each function are in the nested scope region, so they're indented by one level.
